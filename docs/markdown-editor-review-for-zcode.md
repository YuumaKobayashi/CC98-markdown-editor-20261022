## 3. 逐项修改要求

### M01：KaTeX class 不能作为可信内容标记

**位置**

- `markdown-config.ts:45`：允许解析裸 HTML，`html: true`。
- `markdown-config.ts:176–185`：DOMPurify 的 `uponSanitizeAttribute` 钩子。
- 关键判断：`if (node?.closest?.(".katex, .katex-display")) return;`。

**问题与触发条件**

代码假设 `.katex` 子树内的 style 全部来自本站 KaTeX，所以不执行样式属性白名单。但作者可以在裸 HTML 中写同名 class，过滤函数没有验证该节点的生成来源。DOMPurify 对其他危险标签和属性的过滤仍然存在；本问题不能直接等同于任意 JavaScript 执行，明确风险是绕过本站额外设置的 CSS 限制。

在隔离测试页将以下内容传给 `sanitizeHtml`，检查输出及插入页面后的效果：

```html
<div class="katex">
  <a href="https://example.com"
     style="position:fixed;inset:0;z-index:2147483647;background:white">
    测试覆盖层
  </a>
</div>
```

当前分支会跳过上述 style 的本站白名单过滤。最终能否覆盖整页，还需结合实际祖先的 transform、contain、overflow 和层叠上下文验证。

**修改要求**

1. 不以作者可控的 class、data 属性或可在正文中填写的标记认定内容可信。
2. 明确用户 HTML 清洗与公式渲染的顺序。优先在作者 HTML 清洗后生成公式；如果受第三方管线限制，采用兼容公式排版的受限样式策略，并为其建立负面样例。
3. 同时检查 `.katex-display`、元素自身持有 class、嵌套伪造以及 SVG/MathML 场景，不只修示例中的 div。
4. 不要通过修改全局 DOMPurify 钩子后再异步恢复的方式建立临时豁免，以免并发渲染相互影响。
5. 修改过滤规则时，同步核实自定义 CSS 属性及宽泛属性前缀的放行是否确有必要；若发现另一条绕过路径，单独记录证据，不预先认定其构成漏洞。

**验收**

- 伪造上述 class 不再获得任意定位、层级和 transform 权限。
- 普通用户 HTML 的现有排版白名单仍有效。
- 正常分数、根号、上下标、矩阵、aligned 及错误公式均正常展示。
- 直接 Markdown 帖和 UBB `[md]` 内容使用相同安全策略。
- 添加实际调用 `sanitizeHtml` 的 DOM 测试，不能只测试白名单辅助函数。

### M02：历史引用修复不能扫描并改写所有正文

**位置**

- `markdown-preprocess.ts:9`，`preprocessLegacyMarkdown`。
- `markdown-view.tsx:77`，所有 MdPreview 内容都会经过此函数。

**已复现用例 A：代码块正文被修改**

输入：

````markdown
```text
> example
plain

```
````

当前输出：

````markdown
```text
> example
>plain

```
````

原因是全文正则将代码块中的 `> example` 当成旧引用，给后续 `plain` 添加了引用前缀。存储源码未被此函数直接改写，但展示源码已与存储内容不同，复制展示代码也可能带走错误字符。

**已复现用例 B：删除引用后的空行**

输入字符串 `"> quote\n\n# heading"` 变成 `"> quote\n# heading"`。对应路径为 `prefix + parsed.substring(index + 1)`。并非所有后续块都因此改变渲染，但函数确实改变了用户指定的块间分隔。

**修改要求**

1. 将旧引用修复限制在可识别的历史引用模板，不能把所有现代 Markdown 引用都当成坏数据。
2. 优先在 token/语法树层处理；如采用文本扫描，必须识别围栏及相关代码上下文，不能仅用另一个全文替换正则兜底。
3. 保留引用结束后的段落分隔；若历史兼容确实需要改变某种分隔，应有明确样例和预期。
4. 不回写修改后的文本到原帖或草稿。

**验收**

- 用例 A 代码块中的字符保持原样，用例 B 的分隔保留。
- 覆盖反引号/波浪线围栏、不同围栏长度、行内代码、缩进代码、嵌套引用及 CRLF。
- 为真实旧帖引用建立“修复前输入 → 期望展示”的回归样例。
- 检查幂等性：重复预处理不继续叠加引用符或空行。

### M03：统一正文同步，避免同一变化多次全文序列化

**位置**

- `markdown-editor.tsx:279–338`，`guardBareMathPair`。
- `markdown-editor.tsx:947–989`，`guardBareCodeFence`。
- `markdown-editor.tsx:1364–1389`，Vditor `input` 与修复回调。
- `EditorPage.tsx:653`，回调更新父组件状态。

**问题与触发条件**

一次输入会经过 Vditor 自带 input 回调；公式守卫和围栏守卫又在微任务或 DOM 观察回调中无条件执行 `onRepaired`。外层回调调用 `getValue()`，将编辑区转换为 Markdown 后再次上报。即使修复函数返回 false，也存在重复工作。

普通中文/英文输入和第三方渲染导致的 DOM 变化都可能进入这些路径。不能仅凭源码声称每键固定触发几次，应先采样统计。

**修改要求**

1. 修复函数明确报告是否真实改变可序列化内容；无变化时不因“修复”重新上报。
2. 建立实例内统一同步入口，对相同正文去重，并在可行范围内合并同一轮修复。
3. 明确先修复、后通知的顺序，避免先把自动补全的错误围栏版本交给草稿/发帖逻辑。
4. 不给输入显示、IME 提交和最终提交简单套长时间 debounce。若草稿持久化需要 debounce，应与正文即时一致性分开处理。
5. 保证点击发送、清空、切换编辑模式前，父组件能拿到最终内容，不丢失最后一次输入。

**验收**

- 分别记录普通输入、公式输入、粘贴时的 `getValue` 和 `onChange` 次数。
- 不再连续通知相同字符串；一次稳定编辑结果原则上只上报一次，确需中间态时说明原因。
- 对比约 1 KB、10 KB、100 KB 文本，包含代码块/公式的样本，报告同一浏览器和机器上的耗时或长任务变化，不设置未经测量的绝对性能保证。
- 光标、选区、撤销重做和提交内容正确。

### M04：输入滚动控制应由单一可取消任务管理

**位置**

- `markdown-editor.tsx:1589–1620`，`freezeScrollOnInput`。
- `markdown-editor.tsx:1626–1634`，effect 清理函数。

**问题与触发条件**

每次 input 新建独立 `restore` 闭包，保存不同的页面/内部滚动位置，并运行约 31 次动画帧。连续输入可能让多个恢复循环重叠。当前清理没有保存并取消这些 requestAnimationFrame；wheel/touchmove 的监听器由任务自行移除，不属于 effect 的完整清理。

“30 帧约半秒”的注释也依赖屏幕刷新率，不能作为固定时长。滚轮和 touchmove 会释放锁，但滚动条拖动、部分键盘滚动等路径需要单独核实。

**修改要求**

1. 每个编辑器最多一个活动滚动控制任务，新的输入更新或替换该任务，避免多个旧坐标互相竞争。
2. 保存帧 ID，并在结束、卸载、模式切换时取消；完整清理额外事件监听器。
3. 如需时长窗口，按时间戳计算，不能以固定帧数假定毫秒数。
4. 保留现有防止输入跳页的目的，明确哪些由第三方造成的跳动要抑制、哪些为用户主动滚动必须放行。
5. 连续输入到可视区底部时，需保证用户仍能看到光标；不要通过持续回写旧位置让光标消失。

**验收**

- 长按输入或持续输入 5 秒，没有多个独立恢复循环积累。
- 页面滚轮、内部滚轮、触摸滑动、拖动滚动条、PageUp/PageDown、方向键和点击定位分别测试。
- 卸载编辑器后无残留页面滚动操作。
- 放大/收起、窗口尺寸变化和移动端软键盘出现时无明显跳动或光标遮挡。

### M05：公式与代码围栏状态移到编辑器实例内部

**位置**

- `markdown-editor.tsx:48`：`repairHeld`。
- `markdown-editor.tsx:192–216`：重置回调、美元符号快照、块计数、代码围栏状态。
- `guardBareMathPair`、`guardBareCodeFence`、`holdMathRepair` 及其清理逻辑。

**问题与触发条件**

多个编辑器共享模块变量。挂载 B 会重置 A 的计数并覆盖重置回调；在 B 调用 `holdMathRepair` 会影响 A；卸载任一实例会将共享 reset 回调设为 null。即使当前某个业务入口只挂载一个实例，组件本身和多实例 fixture 仍会受到影响。

**修改要求**

1. 使用实例闭包、控制器对象或 useRef 管理上述可变状态；工具栏、外部回填和守卫引用同一实例的控制器。
2. 卸载仅清理本实例；避免依靠“新实例初始化时重置全局变量”补救。
3. 检查排队微任务，已销毁实例的回调不应继续上报内容或访问后来挂载的另一个实例。

**验收**

- 同页挂载 A/B，交替输入美元符号、代码围栏、工具栏建块、外部 value 回填。
- A 有未完成的定界符时，挂载/卸载 B，不改变 A 的识别结果。
- 两实例内容和各自 onChange 日志完全隔离。
- 覆盖 React StrictMode 的挂载/清理/再挂载，验证实际使用的 Vditor 版本可正常工作。

### M06：资源加载区分“存在、加载中、成功、失败”

**位置**

- `katex-loader.ts:18–29`，`injectScript`。
- `katex-loader.ts:44–55`，`ensureKatex`。
- 关联：`markdown-editor.tsx:1018–1043` 的预载，以及 md-editor-rt/Vditor 各自资源加载路径。

**问题与触发条件**

`injectScript` 找到同 src 标签时立即 resolve，但该标签可能仍在下载，随后读取 `window.katex` 会失败。加载失败时 `katexPromise` 保留 rejected Promise，后续调用一直失败。失败标签也可能留在 DOM 中。当前样式注入也没有可供调用者观察的失败状态。

Vditor 与 MdPreview 的资源 URL、标签 ID 和查询参数不完全相同。不要假设对本地 loader 去重就解决了所有第三方并发加载。

**修改要求**

1. 同一资源的并发调用复用加载 Promise；只有目标渲染接口确实可用时才视为就绪。
2. 对已存在且仍在下载的标签等待 load/error，并处理监听安装前已加载的情况。
3. 失败后清理本加载器拥有的失败状态，允许后续调用重试；不要误删其他库仍在使用的正常资源。
4. 考虑加载超时，保证状态能够结束并给出可理解的失败反馈。
5. 核对第三方路径和脚本执行顺序，避免在公式渲染过程中重复执行脚本、覆盖全局对象或引入新竞态。
6. 静态资源继续自托管，核实开发重写和生产复制配置，不替换成外部 CDN。

**验收**

- 慢网下同时展示 Markdown 公式与 UBB `[math]`/`[m]`，不因提前 resolve 报缺少 `window.katex`。
- 同一 loader 的并发调用共用在途任务。
- 首次请求失败，恢复网络后再次请求可以成功。
- 目标接口已存在时正常复用；现有脚本标签仍下载时正确等待。
- 通过实际第三方加载路径测试，不能只用“标签存在且全局对象已存在”的简单 mock。

### M07：文件片段生成需要按上下文转义

**位置**

- `markdown-editor.tsx:1078–1088`，`buildFileMarkdown`。

**问题与触发条件**

图片 alt、附件链接文字直接拼接 `file.name`；音视频 src 直接拼接 URL。Markdown 与 HTML 属性所需转义不同，不能共用一次泛化替换。当前服务通常返回受控 URL，但组件接口本身只约束返回字符串。

示例：图片或附件名为 `report].png`、`a[b].txt` 时，会引入未转义的方括号；URL 含圆括号、空白等字符时也应保证链接可解析。带双引号的 URL 用于 HTML src 时需要属性编码。测试文件名应符合测试操作系统限制；无法在 Windows 文件系统创建的名字可用内存 File 对象测试。

**修改要求**

1. 图片 alt 与链接文字按所用 Markdown 解析规则转义；目标 URL 使用解析器支持的安全表示，避免双重编码。
2. 音视频 URL 按 HTML 属性上下文编码。
3. 根据上传服务合同验证返回 URL；明确接受的协议/站内相对路径，不接受脚本协议。不要把 URL 编码误当成协议验证。
4. 保留原始可见文件名，不以简单删除特殊字符作为主要方案。
5. 不依赖最终展示的 DOMPurify 掩盖编辑器内的错误片段。

**验收**

- 覆盖中英文、空格、方括号、反斜杠、括号及 URL 查询参数。
- 文件名如 `a[b].png`、`report].txt` 在编辑和展示时都只生成一个完整图片/链接。
- URL 中含合法特殊字符时地址不被截断，已有百分号编码不被重复破坏。
- 生成音视频片段时，返回值中的引号不能形成额外 HTML 属性。
- 图片、音频、视频、普通附件四类结果均通过编辑器与展示端回归。

### M08：上传队列需要覆盖异常、并发和异步生命周期

**位置**

- `markdown-editor.tsx:1128–1168`，`handleUploadFiles`。
- `markdown-editor.tsx:1356–1361`，Vditor 粘贴/拖拽入口。
- `markdown-editor.tsx:1719–1724`，文件选择入口。
- `editor-image-upload.ts` 默认适配函数与 `src/modules/upload/api/service.ts`。

**问题 A：异常中断整批**

批量循环只有 finally，没有逐文件 catch。注入的上传回调如果 reject，后续文件不会继续上传，且前面成功积累的 snippets 尚未插入。调用处使用 `void handleUploadFiles(...)`，也没有接住该 rejection。默认上传服务通常自行捕获异常，因此应将其描述为组件错误处理缺口，而不是声称正常网络失败必然触发未处理异常。

**问题 B：多个入口可并发启动**

文件选择通过 React state 判断 uploading，粘贴/拖拽没有相同入口保护。两个任务可以重叠，第一个任务结束就把 uploading 设为 false，即使第二个仍在上传。

**问题 C：完成时的目标和光标没有明确契约**

请求期间用户可能移动光标、清空内容或切换编辑器。当前代码在整批完成后向“届时的当前光标”插入，未记录文档版本或插入锚点。是否出现错位需浏览器验证；在没有明确产品规则前，不直接宣称必须恢复到旧光标。

**修改要求**

1. 逐文件捕获异常；失败可报告且不吞掉同批已成功的结果，最后统一恢复状态。
2. 文件选择、粘贴、拖拽使用同一队列或同一并发控制。明确忙碌时是排队还是拒绝，反馈一致。
3. 使用同步 ref/控制器管理活动任务，不能仅依靠异步更新的 React 布尔 state 防重入。
4. 保持选择顺序；如引入有限并发，要保存结果索引，不按请求完成顺序插入。
5. 明确上传期间移动光标的插入策略；清空、换稿、卸载后的旧请求结果不得误插入新稿或另一个编辑器。
6. 如服务支持，使用 AbortSignal；不支持时至少用实例/稿件标识忽略失效结果，并提供可理解的处理结果。
7. 不强制为性能改成无限并发。上传上限、失败返回值和错误提示与现有服务合同保持一致。

**验收**

- 三文件依次成功、reject、成功：两个成功结果保留，失败文件有提示，无未处理 Promise rejection。
- 拖入文件后立即粘贴图片，队列状态和最终内容正确。
- 空列表、全部超限、部分超限、返回空字符串、抛异常均有测试。
- 请求未结束时清空/换稿/切换模式/卸载，再完成旧请求，不能污染后续稿件。
- 上传期间移动光标的实际行为与约定一致，重复选择同名文件仍有效。

### M09：按职责拆分实现，集中第三方 DOM 适配

**位置**

- `markdown-editor.tsx`：输入修复、符号配对、缩进、资源预载、上传、工具栏、复制、滚动、弹层与 React 生命周期均在同一文件。
- 尤其是 `.vditor-ir`、`.vditor-reset`、`.vditor-ir__marker--pre` 等内部结构依赖。

**问题与修改要求**

当前结构让一次局部改动难以判断是否影响光标、序列化或撤销。拆分目标应是隔离状态和生命周期，不是把一个大函数机械切成多个文件。

建议边界，实际命名可由实施者调整：

- 实例级 Vditor 适配：初始化、销毁、ready、get/set/insert、统一同步入口。
- 输入行为控制器：公式/围栏修复、成对符号和缩进，暴露明确的安装/销毁接口。
- 文件功能：片段生成、队列及生命周期控制。
- 展示辅助：代码复制按钮、测量定位、滚动协调。
- React 组件：组合上述能力，负责工具栏、弹层和交互状态。

1. 将内部选择器和第三方假设集中到适配层；DOM 不符合预期时安全退出并提供开发期诊断。
2. 维持 `MarkdownEditorProps` 兼容，含 uploadImage/uploadFile 的现有调用方式。
3. 对定界符修复的必要性保留简洁注释和回归用例；历史讨论、图标设计过程等长叙述可迁到文档。
4. 与行为修复分步提交，避免一次同时大规模搬文件和改变输入语义。

**验收**

- M01–M08 的测试在拆分前后保持通过。
- 发帖、编辑帖子、回帖、UBB 内嵌 Markdown 四类入口正常。
- 无新增反向业务依赖；资源仍自托管；没有偷偷替换编辑器框架。

### M10：补齐真正执行自定义行为的回归测试

**位置**

- `scripts/check-math.cjs`：直接调用 Vditor 携带的 Lute，只检查解析计数及部分往返。
- `package.json`：当前命令提供 typecheck 和 test:math。
- `src/application/routes/dev/visual-fixtures/VisualFixturePage.tsx`：存在 Markdown fixture，可作为浏览器测试入口候选。

**覆盖缺口**

现有脚本通过，不表示守卫、事件顺序、MutationObserver、上传、滚动和选区逻辑正确。它也没有对比编辑端 Lute 与展示端 md-editor-rt 的输出。编辑器注释中提到浏览器 harness，实施者应先搜索当前代码包是否实际包含可运行 harness，再决定复用或新增，不凭注释认定已有覆盖。

**修改要求**

1. 纯函数测试：历史预处理、片段生成、语言/缩进等有实际分支的逻辑。
2. DOM 安全测试：调用实际 sanitizeHtml，包含 M01 负面样例及合法 KaTeX 排版。
3. 浏览器测试：加载真正 Vditor 和站点守卫，不以模拟函数替代关键交互。
4. 共享语法样例分别经过编辑与展示管线，验证语义一致性；不要求两库 DOM 字符串逐字相同。
5. 性能采样与功能断言分开，减少与机器速度强绑定的脆弱阈值。

**最低浏览器回归矩阵**

| 类别 | 操作 | 核心断言 |
| --- | --- | --- |
| 定界符 | 空行连续输入 1–4 个美元符号 | 输入不被吞掉、不擅自增加源码字符 |
| 公式 | 完整行内/块公式、工具栏空公式、粘贴现成公式 | 内容正确，源码可继续编辑 |
| 围栏 | 手输围栏并回车、工具栏建块、粘贴代码块 | 没有重复围栏或额外正文字符 |
| 中文输入 | compositionstart/update/end、候选上屏 | 组合期间不破坏文本和光标 |
| 编辑 | 代码中配对/跳过闭符/删除配对/回车缩进 | 正文正确，选区不越界 |
| 历史 | Ctrl+Z/Ctrl+Y 及工具栏撤销重做 | 恢复真实编辑步骤，守卫不反复改写历史 |
| 同步 | 草稿载入、外部回填、提交清空、最后一键后立即提交 | 不丢最后输入，不提交修复前中间态 |
| 多实例 | A/B 交替输入，挂载和卸载 B | A 状态不受 B 影响 |
| 上传 | M07/M08 的转义、失败、并发与换稿场景 | 无错误片段、丢结果或稿件污染 |
| 滚动 | 长文持续输入、手动滚动、放大收起 | 光标可见，无卸载后滚动残留 |
| 加载 | 慢网、首请求失败再重试 | 不提前就绪，不永久失败 |
| 展示 | 引用、围栏、裸 HTML、表格、公式、附件 | 两端核心语义一致，安全规则有效 |

真实输入法的候选交互可能不能被自动化 composition 事件完全替代。至少补一次真实中文输入法人工验收，并记录浏览器、操作系统和输入法。

## 4. 推荐实施顺序

1. 建立 M01/M02 的失败用例，修复安全过滤和内容预处理。
2. 修复 M06 加载竞态；补慢网和失败重试测试。
3. 修复 M05 实例隔离，再处理 M03 正文同步；两者共享状态管理边界。
4. 修复 M04 滚动任务生命周期。
5. 修复 M07/M08 文件片段与上传队列。
6. 在行为稳定的基础上执行 M09 职责拆分；M10 测试伴随每一步补齐。

## 5. 完成标准与交付格式

实施后运行：

```sh
npm run typecheck
npm run test:math
npm run build
```

另运行新增的单元/DOM/浏览器测试；在 package.json 中提供可重复的命令。若受环境影响不能运行构建或浏览器测试，明确写出失败命令、原因和未验证范围，不能记为通过。

Zcode 最终交付应包含：

- M01–M10 逐项状态：已修复、已验证无需修改、或仍待处理。
- 每项实际修改的文件、主要设计选择及与本文要求的差异。
- 自动测试命令与结果；浏览器/真实输入法人工验证结果。
- 性能优化前后使用同一样本的对比数据。
- 未解决问题和必要的产品行为决定，尤其是上传插入位置和光标跟随策略。

不要把“类型检查通过”“公式解析脚本通过”作为全部交互问题已经解决的证明。
