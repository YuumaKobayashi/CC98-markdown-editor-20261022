# P5.3：核心 module 类型与 API 收口验收报告

执行日期：2026-08-03

本报告只覆盖 P5.3。实施起点为干净的 `dev20260716`（相对 `backup/dev20260716` ahead 3），主后端为干净的 `master@c46f2fa4`。本批按 User/Session、Notification/Message、Board、Topic/Post、Site Content/Home 顺序纵向收口；没有删除兼容 facade、dormant export 或旧别名，没有执行写接口，没有进入 P5.4。

## 1. 结论

- User、Session、Message、Notification、Board、Topic、Post、Site Content 的 wire/request 类型已收口到各自唯一 `model/dto.ts`；编辑器状态和组件 Props 留在 UI owner。
- 全仓仅有 Topic、Post、Message、Notification 四个 `model/mappers.ts`。mapper 接收只读 DTO/内部只读 source 与已完成的补查结果，返回新对象，不修改 response。
- `FocusTopic` 不再覆盖 raw 的时间、计数、tag id、用户名或媒体字段；展示值使用 `displayTime`、`displayLastPostTime`、`displayHitCount`、`displayReplyCount`、`tag1Name`、`tag2Name`、`boardName`、`portraitUrl` 等独立字段。
- `as unknown as PostViewModel`、DTO 宽联合入口和调用者任意指定返回类型的泛型已从目标闭包移除。首帖、特定用户、普通追踪、匿名追踪继续由独立 endpoint 函数表达。
- Topic API 已按 `detail.ts`、`list-search.ts`、`metadata.ts`、`history.ts` 四个业务闭包拆分；`service.ts` 只保留兼容聚合出口。URL、method、query、Header、分页、补查顺序与异常吞吐保持原逻辑。
- typecheck、production build、浏览器只读烟雾和目标静态扫描通过；最终机械与字节检查见第 7 节。当前停在人审点，不 commit、不 push、不进入 P5.4。

## 4. 宽类型、nullable 与兼容债务

- Topic 后端 `TopicInfo` / search 投影把 `mediaContent` 声明为 `object`，且运行时会随图片、音频、视频类型变化，因此 wire 保留 `unknown`。唯一 Topic mapper 在边界内只读检查字段后生成 `MediaTopicContent | null`；没有断言成固定 wire 结构。
- `TopicAudioPlayer` / `TopicVideoPlayer` 中两个 `player: any` 属于旧版 APlayer/DPlayer CommonJS 包的动态实例边界；本批未改播放器控制流，后续只有在补齐可靠第三方声明后才能移除。
- Site editor 的 `days?: number | string` 是 UI 输入状态，不是 wire DTO；提交时显式转换为可选 `number`。
- `BoardInfo | "not found" | ...`、吞异常返回 `undefined/null/false` 等旧错误合同按计划留给 P5.5，本批没有改变错误语义。
- 主后端已注释的 `/post/topic/user`、`/post/topic/anonymous/user` 没有安全的当前样本；兼容函数和 DTO 不提前删除，登记到 P5.6/后端清理决策。

## 5. mapper、mutation 与 API 闭包扫描

- mapper 文件数量为 4：Topic、Post、Message、Notification；User、Session、Board、Site Content 没有空 mapper。
- `as unknown as`、`as Mutable*`、DTO/ViewModel 交叉伪装、目标 model 中残留组件 `*Props`、`MainPageTopicMoreProps` 均为 0。
- mapper 与 API 的 raw DTO 赋值扫描没有输入对象写入；Message/Notification 的补充用户、主题、版面查询均在 mapper 外完成。
- Topic mapper 使用内部 `FocusTopicSource` / `RecentTopicSource` 表达转换所需的公共只读投影；公开 API 仍按真实 endpoint 返回 `TopicInfo`、`SearchedTopicInfo`、`PostInfo` 等明确 DTO，不暴露宽联合或调用者泛型。
- `getTopicInfo`、普通/匿名追踪及 `PostViewModel.postId` 只接受后端整数标识；React Router 的字符串参数在 Route/UI 入口解析，module API 不再把字符串伪装成 endpoint 能力。
- Topic 四个子文件按 detail、list/search、metadata、history 聚合业务能力；没有按 HTTP method 或一 endpoint 一文件机械拆分。`service.ts` 的旧导入路径继续工作。
- module 级静态图仍只有既有的 `post <-> topic` 与 `session <-> user <-> user-preference` 两个循环 SCC；目标 module 内没有 self-barrel。
