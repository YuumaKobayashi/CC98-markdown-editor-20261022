# P5.0：基线与规则冻结

执行日期：2026-08-03

本报告只覆盖 P5.0。前端当前提交为 `28fdc766`，Phase 5 业务代码基线为 `b33f9dd6`，主后端契约基线为 `c46f2fa4d340c606b42764a05d106f178d91bc3c`。本批没有修改业务代码、公共类型、URL、请求协议、Redux/Storage 或组件行为。

## 1. 结论

- 类型、API owner、公共入口和错误合同规则按本文第 2 节冻结；后续 P5.x 只能按独立子批修改，不能在迁移请求所有权时顺带改变错误协议。
- endpoint owner 清单、16 个 `api/` 外请求文件、宽类型分类和字符串错误消费者均已闭合；dormant 出口继续登记，不因本批恢复可达性或删除。
- 已在宿主机外部复核 `127.0.0.1:25174`：Node PID `16236` 监听，`/` 与 `/static/config.json` 均为 200；没有重启或替换现有开发服务。
- 内建浏览器已从本地前端完成公开、登录后只读基线。业务 API 只观察到 `GET`；跨域带 Header 的请求同时出现浏览器自动发送的 `OPTIONS 204` CORS 预检。唯一主动写式请求是获准的登录 token 请求。
- 浏览器未执行签到、通知已读、主题设置、私信、关注/收藏、发帖、评分、版务或任何账号/版面写操作。用户要求保留当前登录会话，因此没有退出登录；标签页停在本地版面 `245`，开发服务器继续运行。
- 主题详情页操作失败时出现的黑框是用户确认的既有 CSS 缺陷；P5.0 不修改、不验收该视觉问题，也不将其计为 API/类型回归。

## 2. 冻结规则

### 2.1 类型与 mapper

| 类别 | 冻结定义 | 位置与约束 |
| --- | --- | --- |
| DTO | API 实际发送或接收的 wire 数据 | `module/model/*-dto.ts`；忠实保留 nullable、缺失、基础类型和时间字符串，不混入 UI 字段 |
| ViewModel | DTO 经补充查询、格式化或聚合后的页面模型 | `module/model/*-view-model.ts`；没有真实转换时不创建 |
| Form/Draft | 编辑中、未提交的本地状态 | Route 或 module `model/*-form.ts`；不得冒充 request DTO |
| Props | 单个组件输入 | 组件附近；不提升为领域 DTO |
| State | Redux、Session、缓存或页面状态 | 对应 owner；与 wire DTO 分开 |

- Request DTO 也属于 DTO，放在 `model`；`api/` 只放请求及响应处理。
- enum 与所属 DTO/模型共置；大 module 按业务能力拆分，不恢复统一语法型 `enums.ts`。
- 单调用者且短小的转换留在调用文件私有函数；多调用者或复杂转换才提升为 ViewModel mapper。mapper 必须为纯函数，不能自行发请求。

### 2.2 API owner 与公共入口

- `cc98Fetch` 只允许出现在 `foundation/api` 或资源所属 module 的 `api/`。
- API 函数接收 primitive、DTO、`File/Blob`，不接收 React setter、DOM event 或 AntD FormInstance；页面继续拥有交互顺序和 UI state。
- `foundation/config/runtime-config.ts` 的启动配置加载是 Foundation 特例；`/static/portrait.json` 归 User，文件上传归 Upload。
- 跨 module 允许稳定的 `@modules/<owner>/api|model|ui/...` 子路径。根 `index.ts` 是可选稳定 facade，不再是唯一入口；旧根出口在消费者归零前保持兼容。
- module 内使用相对路径，禁止 self-barrel；cache/internal helper 不因存在就自动成为公共 API。

### 2.3 错误合同

- 普通 API 成功返回 DTO 或 `void`；技术失败抛出 `{ kind, message?, status? }` 形状的 `ApiFailure`，其中 `kind` 仅限 `unauthorized | forbidden | not-found | validation | server | network | invalid-response`。
- 评分等正常业务拒绝使用 `{ ok: false, error: { kind, message? } }` 的 discriminated result；网络、500 和无法解析仍走 `ApiFailure`。
- 禁止新增 `"ok"`、`"error"`、`"unauthorized"` 等裸字符串结果。
- 请求所有权搬迁与错误合同改变不得同批：先等价迁移，再单独修改返回协议和全部消费者。

## 4. 宽类型分类

nullable 且已由后端/浏览器证明的字段不是类型债务；下表只登记仍需解释或分层的宽类型。

| 分类 | 位置 / producer → consumer | 冻结处理 |
| --- | --- | --- |
| dormant 未知响应 | Board/Topic/Post Rating/Reaction/User 的 19 个 dormant 出口与 6 个未约束 JSON 边界 | 保持不可达；重新启用时逐 endpoint 建 DTO |
| wire → ViewModel 加工 | Topic/Post、Message、Notification service 原地补用户、版面、展示时间、楼层 | raw DTO 与加工结果分离；mapper 纯函数 |
| 匿名/权限相关 nullable | Topic `userId/userName`、Board `bigPaper/description/lastPostContent`、User 隐私字段 | 保留 nullable；单个登录样本不得收窄 |
| dynamic media | Topic `mediaContent: unknown`、音视频播放器实例 | 建立按媒体类型的 union 后再收窄；第三方实例单列 |
| Board 页面 state | list/topList、preview posts、selection、错误哨兵、tag cache | 先拆 DTO/ViewModel/错误通道，再改 state；不局部断言 |
| Topic Detail 页面 state/Props | TopicPage/TrackedTopicPage、Reply/Header/Signature/Replier 的 `any` 传播 | 以页面 producer 为闭包一次收窄；不逐组件伪造 |
| Editor Form/Draft | EditorPage、vote/tag/housing 表单与 `number | string` wealth | 分成 route form、request DTO 和响应；不冒充 wire DTO |
| storage/cache | Board/tag/user/draft/web-storage 反序列化边界 | 需 key schema、版本化和运行时校验；当前不强行收窄 |
| Redux/legacy effects | Session sync、legacy utility effects | 统一 AppDispatch 和移除 bridge 后处理 |
| Router/lazy module | legacy route props、lazy module、navigation state | 建 route module map 后收窄 |
| 第三方/插件 | Spectrum、APlayer、Hls、DPlayer、动态 UBB payload | 补声明并逐插件验收，不伪造领域 DTO |
| 首页/New Topics 聚合 | route UI 直连请求、缓存、分组投影 | 请求先归 owner，再建立 route ViewModel |
| AntD 动态表单/表格 | Moderation、Site Advertisement、Board selection | 先建立 key/value 或事件值域，再收窄 |
| Foundation 动态值 | time 格式化、debounce options、theme storage | Foundation 独立清理；不与 P5 API 迁移混批 |
| 兼容出口 | `IUser/ITopic/IPost/IBoard/ISignIn` | 消费者归零后在 P5.6 删除；当前保留 |

## 6. 浏览器只读基线

### 6.1 环境与安全边界

- 前端入口：`http://127.0.0.1:25174/`；根 HTML 和 `/static/config.json` 为 200。
- runtime config：API 为 `https://api.cc98.org`，OpenID 为 `https://openid.cc98.org`。
- 通过本地 `/logOn` 可见表单提交了一次获准登录；登录成功并进入既有重定向 `/newTopics`。登录请求和响应体未落盘，CDP 缓冲在大量 Vite 模块事件后发生截断，因此 token 事件没有作为可保存样本；目标 origin 由 runtime config 与活动 Session 实现共同确认。
- `/me` 只保存字段名、nullable 和基础类型，不保存字段值；账号、密码、Authorization、token、Cookie、登录 body 和私人字段值均未写入本文或仓库。
- 用户明确允许保留登录态；未读取 cookie、localStorage、浏览器密码存储，也未尝试第二次登录。

### 6.2 路径与请求结果

| 页面 | 观察到的主要请求 | 结果 |
| --- | --- | --- |
| `/` | local config/theme/assets；首页已有内容 | 应用 bootstrap 成功；既有 UBB/key warning 另行登记 |
| `/boardList` | `GET /Board/all` | 200；12 个分区；分区首项字段为 `id/name/order/masters/boards` |
| 匿名 `/board/245` | alltag、board info | 两个 GET 均 200；`canEntry` 导致页面转 401，符合匿名权限分支 |
| 登录后 `/newTopics` | `/me`、unread-count、board/all、random-recent、new-media、user/basic | 全部 GET 200 |
| 登录后 `/board/245` | board、advertisement、tag、top topics、board topics | 全部 GET 200；页面可进入 |
| 登录后公开主题 | topic、board、isfavorite、posts、user、reward record、hot-post | 全部 GET 200；未触发 read/write 标记 |

所有带授权 Header 的跨域 GET 同时观察到 `OPTIONS 204`，这是浏览器 CORS 预检，不是业务写操作。除登录外没有观察到 POST/PUT/DELETE/PATCH。

### 6.3 字段形状证据

- `BoardInfo`：匿名样本中 `bigPaper/description/lastPostContent` 可为 `null`，登录后版面 245 样本为字符串；`logoUri` 仍为 `null`。现有 nullable 必须保留。
- `TopicInfo`：匿名主题样本 `userId/userName/userInfo` 为 `null`；时间为字符串，state/type/tag/count 为数字，布尔标志保持 boolean。
- `PostInfo[]`：主题样本中 `userId/title/allowedViewers/lastUpdateTime/lastUpdateAuthor` 可为 `null`，`content/time/ip` 为字符串，floor/count/state 为数字。
- `/me/unread-count`：`systemCount/atCount/replyCount/messageCount` 均为数字。
- `/config/global/advertisement`：数组元素包含数字 `id/type/orderWeight`、字符串 URL/time、nullable content 与 boolean enable。
- `reward-daily-record`：样本为 `rewardType/rewardTotalValue/rewardMaxValue` 三个数字字段；仍不以单样本证明非 nullable。
- `mediaContent` 在普通主题样本为 `null`，在 new-media 样本为带 `thumbnail` 数组的对象，支持继续保留宽类型并在后续建立 discriminated union。

### 6.4 版面标签扩展样本

用户补充授权后，以登录态只读复测 6 个可见版面；每个页面只产生 `GET` 与对应 `OPTIONS`：

| board | `GET /board/{id}/tag` | 形状 |
| --- | --- | --- |
| 245 | 200 | 1 组；`layer: number`，`tags` 3 项 |
| 135 | 200 | 空数组 |
| 788 | 200 | 1 组；`tags` 7 项 |
| 182 | 200 | 空数组 |
| 81 | 200 | 空数组 |
| 68 | 200 | 1 组；`layer: number`，`tags` 7 项，tag 为 `{ id: number, name: string }` |

结论：`BoardTagInfo[]` 的数组可以为空；非空项稳定为 `{ layer: number, tags: Array<{ id: number; name: string }> }`。这些样本没有出现多层数组，但单样本不能把 `layer` 收窄为常量，也不能假定所有版面都有标签。
