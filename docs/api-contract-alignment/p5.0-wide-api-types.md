生成日期：2026-08-03

## 1. 口径

- `wire DTO`：直接描述后端 JSON；应与后端公开类型、序列化结果一致。
- `request DTO`：会进入 URL、query 或 `JSON.stringify`；后端为 `int` 时，前端 Route 字符串不应长期扩散为 `number | string`。
- `ViewModel/Form`：前端格式化或编辑态；允许比 wire DTO 宽，但必须明确不是后端类型。
- `service 控制流`：`null`、`undefined`、`false`、数字或字符串错误哨兵；不是 JSON 字段，却会迫使所有消费者处理宽联合类型。
- “后端已确认”只表示固定提交的 C# 声明支持该类型；运行时是否在所有权限、匿名、空数据分支出现，仍需逐 endpoint 样本验证。

## 8. 人工核验建议顺序

1. 先看第 2 节：确认哪些宽类型确实要拆 DTO/ViewModel/Form，而不是简单删除联合分支。
2. 再看第 4 节：这些 `null` 有后端源码依据；只有发现 action 投影保证非空，才能局部建立更窄的 endpoint DTO。
3. 对第 7 节逐 endpoint 保存正常、空数据、匿名和无权限响应字段形状；写接口继续保持未执行，除非另行授权。
4. 最后处理第 6 节错误合同；不得与 API owner 搬迁放在同一子批。

本清单是静态源码与既有只读样本的核验入口，不声称已完成所有 endpoint 的运行时 schema 验证，也不把 `npm run typecheck` 当作后端契约一致性证明。
