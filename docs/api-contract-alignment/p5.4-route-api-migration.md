# P5.4：Route API 拆回 module 验收报告

## 1. 范围与结论

本批以干净的 `dev20260716@c0f4efff` 为起点，主后端合同基线为 `master@c46f2fa4`。Board、Editor、Topic Detail 三组 Route 私有 API 已按 endpoint 资源 owner 迁回业务 module；三个 Route `api/service.ts` 及 Board Route 的 API barrel 出口已经删除，调用点全部切换到 `@modules/*`。

原有 23 个 Route API 导出最终闭合为 21 个 module 入口：无约束泛型 `getTopics<T>` 按其 TODO 拆成具体 endpoint 函数，Editor 与 Topic Detail 两份 `POST /notification/at` 合并为 Notification 的单一入口。P5.4 没有改变页面的 status、JSON、text 或异常处理；11 个仍需原始响应的 module API 继续返回 `Promise<Response>`，明确留给 P5.5。

本批只执行 GET/read-only 验收，没有发送关注、投票、回复、发帖、编辑、批量管理或公告写请求。当前停在人审点：未 stage、未 commit、未 push、未进入 P5.5。

## 2. endpoint 与 owner 闭包

| Route 原能力 | endpoint | 最终 owner | P5.4 合同 |
| --- | --- | --- | --- |
| 版面详情、Editor 版面读取 | `GET /board/{id}`、`GET /Board/{id}` | Board | 版面页复用既有 typed 入口；Editor 保留原始 `Response` 和 URL 大小写 |
| 版面标签、公告 | `GET /board/{id}/tag`、`PUT /board/{id}/big-paper` | Board | 标签返回 `BoardTagInfo[]`；公告命令保留 `Response` |
| 普通/精华/保存/标签/置顶主题 | 五组 Board Topic GET | Topic list/search | 每个 endpoint 使用具体 DTO；404/500 字符串协议保持不变 |
| 主题投票 | `GET|POST /topic/{id}/vote` | Topic detail | GET 返回 `VoteInfo`；POST 保留 `Response` |
| 主题速览、Editor 原始发言 | `GET /topic/{id}/post?from=0&size=10`、`GET /post/{id}/original` | Post | 速览保留 404/500 字符串；Editor GET 保留 `Response` 和 403 消费 |
| 批量删除、批量锁定、版面事件 | `PUT /topic/multi-delete`、`PUT /topic/multi-lock`、`GET /board/{id}/events` | Moderation | 多值 `id` query、`reason/value` body 与事件分页不变 |
| 关注/取消关注 | `PUT|DELETE /me/followee/{id}` | Follow | 保留 web-storage token、动态 method 与 `Response.status` |
| 创建主题、编辑发言、提交回复 | `POST /board/{id}/topic`、`PUT /post/{id}`、`POST /topic/{id}/post` | Posting | 保留 token 来源、Content-Type、JSON body 与 `Response` |
| @ 通知 | `POST /notification/at?topicid=&postid=` | Notification | 两个 Route 调用统一；用户名数组 body 与 `Response` 不变 |

Route/UI/model 的目标扫描中不再存在 `cc98Fetch`、`formAuthorizeHeader`、`fetch(...)`、旧 `../api/service` 或三个已删除 Route API 路径。Editor 对 `response.status`、`response.json()`、`response.text()` 的现有消费刻意保留，等待 P5.5 把解析和错误协议收回 owner。

## 3. Editor Form/Draft 与 request DTO

Posting 新增 `NewTopicRequestDto`、`NewPostRequestDto`、`NewVoteRequestDto`：

- `NewVoteRequestDto` 与后端 `NewVoteInfo` 的 `voteItems/expiredDays/maxVoteCount/needVote` 一致，`missing=[]; extra=[]; incompatible=[]`。
- `NewPostRequestDto` 覆盖后端 `NewPostInfo` 接受的字段，`tag1/tag2` 仅允许数字或省略；原 `number | false` 已删除，`extra=[]; incompatible=[]`。
- `NewTopicRequestDto` 只暴露当前 Editor 实际发送且后端接受的字段；普通主题不生成 `isVote/voteInfo`，投票主题在既有校验通过后生成 `isVote: true` 与独立 vote request。后端有默认值、当前页面不发送的 `topicContentType/allowedViewerState/allowedViewers/isPosterOnly/shareState` 没有伪造到 body。
- `EditorVoteInfo` 继续作为包含 `0` 临时值的页面 Draft；`EditorVoteSettingsProps` 已共置到组件文件，Route model 不再声明组件 Props 或 wire request。
- 标签名为空仍由既有页面校验处理；非空标签查询失败或出现二级标签缺少一级标签时，转换显式返回失败并提示重新选择，不会把 `false`、空字符串或未解析值交给 `JSON.stringify`。

主后端静态对照覆盖 `TopicController.PostTopic/UserVoteAsync`、`PostController.EditPost/GetOriginalPost`、`NotificationController.AtUser`、`ManageController.MultiLockTopics/MultiDeleteTopics/ChangeBoardBigPaper`、`MeController.FollowUser/UnfollowUser`。请求 URL、method、Authorization、Content-Type、query、body 字段和值域均与迁移前一致。
