# P5.2：低耦合只读 API 迁移验收报告

执行日期：2026-08-03

本报告只覆盖 P5.2。实施起点为干净的 `dev20260716@e99f2c15`，后端契约仓库已核对为干净的 `c46f2fa4d340c606b42764a05d106f178d91bc3c`。本批迁移 BoardList、用户头衔、Recent Topic/Post、unread count、portrait 配置和 Daily Signin GET；没有删除兼容 facade、旧类型别名、现有注释或 dormant closure，也没有执行写接口。

## 1. 结论

- 六个子组的只读请求已归入各自 module API owner；迁移消费者使用稳定的 `api/model/ui` 子路径，根 facade 继续兼容。
- 请求 URL 大小写、method、query、Header、分页多取一条、版面名补查顺序、缓存、Redux/localStorage、错误吞吐和日志行为保持不变。
- Topic/Post 各只有一套 `dto.ts`、`view-model.ts`、`mappers.ts`。新增 mapper 接收只读 DTO 与显式 `boardName`，只返回新对象，不原地改写 response。
- 改前、改后同一组 11 个只读 GET 均为 200；根形状、字段集合、nullable 样本、空数组和时间字符串形状一致。owner API 运行时抽查与原始响应相符。
- modern typecheck、production build、`git diff --check`、直接请求边界、循环 SCC、self-barrel、产物和页面烟雾检查通过；没有新增循环 SCC。
- 当前停在人审点：未 commit、未 push、未进入 P5.3。

复用同源已授权页面，通过应用已有授权 Header 构造函数发送 GET；没有读取或记录账号、密码、token、Cookie 或 localStorage。下表请求在改前、改后均为 200，字段集合与根形状一致。

## 4. 分层、import 图与正式产物

### 4.1 所有权与直接请求边界

- Board、User、Notification、Daily Signin 的目标 GET 只存在于对应 module `api/service.ts`。
- Recent Topic/Post 的 GET、JSON 解析与 mapper 调用只存在于 Topic/Post API owner；Route/UI/model 不再直接拥有这些边界。
- Daily Signin Route 仅保留计划明确排除的 `POST /me/make-up-missed-signin` 及其 JSON 解析。
- 新 mapper 没有 mutation 语句、双重断言或 `any`；`boardName` 作为显式参数进入新 ViewModel。
- 新迁移消费者不通过 module 根 facade；module 内没有 self-barrel。
